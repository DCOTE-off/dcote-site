# Структура клиентской части

Сайт загружает готовые для браузера файлы из `public/css` и `public/js`.
Каталоги `resources/js` и Vite не являются точкой входа для описанных ниже
страничных скриптов. Они используются для проверки глобальных стилей,
начальной настройки JavaScript и производственной сборки.

## Уровни ресурсов

1. `resources/views/layouts/app.blade.php` подключает общие шапку, подвал, `public/js/main.js` и CSS.
2. Каждая страница добавляет собственные ресурсы через `@push('styles')` и `@push('scripts')`.
3. Повторно используемая логика хранится в `public/js/components`, а логика конкретных страниц — в `public/js/pages`.
4. Повторно используемые стили хранятся в `public/css/components`, а страничные переопределения — в `public/css/pages`.

CSS компонента следует подключать перед CSS страницы. Так базовые стили остаются
предсказуемыми, а страница может переопределить размеры или расположение без `!important`.

## Основные интерактивные модули

### Общая оболочка сайта

`public/js/main.js` отвечает только за поведение, общее для всего сайта:

- CSS-переменные высоты окна и шапки;
- жизненный цикл уведомлений;
- мобильное меню и меню учётной записи;
- скрытие нижней мобильной навигации при открытии экранной клавиатуры.

Селекторы, относящиеся к отдельным страницам, сюда добавлять не следует.

### Главная страница

`public/js/pages/dcote_main.js` состоит из трёх независимых частей:

- рейтинг классов и FLIP-анимация переключения спойлеров;
- карусель популярных материалов;
- полоса прокрутки ленты обновлений.

Рейтинг использует существующие DOM-карточки как повторно используемые оболочки.
Перед изменением порядка скрипт запоминает их исходные координаты, обновляет
содержимое и порядок в DOM, после чего анимирует карточки от старого положения
к новому. Измерения DOM должны выполняться до его изменения, а анимация — после.

### Списки сезонов аниме и томов ранобэ

`public/js/pages/anime/season.js` намеренно используется на обеих страницах.
Общая сортировка работает с `.grid-area`, а поведение, относящееся только
к сериям, включается атрибутом `data-collapsible-episodes`.

Важные данные, передаваемые из Blade:

- `data-server-now` и `data-appear-at` позволяют считать время выхода относительно серверных часов;
- `data-episode-number` определяет локальное состояние просмотра и закладки;
- `data-is-upcoming` отделяет будущие серии от вышедших;
- `data-sort-direction` хранит текущее направление сортировки DOM.

Сортировка также использует FLIP. Нельзя заменять перестановку DOM визуальным
порядком через CSS: логика сворачивания и клавиатурная навигация должны
соответствовать отображаемому порядку элементов.

### Настройки чтения

`public/js/pages/reading-settings.js` хранит единый объект настроек в памяти
и синхронизирует его с локальным хранилищем. CSS-переменные являются интерфейсом
отрисовки, а элементы управления только считывают и отображают значения.

Позиция чтения восстанавливается только тогда, когда сохранённый адрес страницы
совпадает с адресом текущей главы.

### Галереи изображений

`public/js/components/image-carousel-modal.js` и
`public/css/components/image-carousel-modal.css` совместно используются
страницами школы и тома ранобэ.

Необходимая структура разметки:

- `.embla > .embla__container > .embla__slide`;
- изображение с классом `.carousel-img` внутри каждого слайда;
- `#imageModal` с навигацией, ссылкой скачивания, фоном и `#modalTargetImg`.

Атрибут `data-caption-from-alt` следует добавлять к `#imageModal` только тогда,
когда текст `alt` изображения нужно копировать в `#modalCaption`.

## Правила анимаций

- Учитывать `prefers-reduced-motion`.
- Хранить длительность и функцию плавности рядом с логикой соответствующей анимации.
- Использовать CSS-классы для постоянных визуальных состояний, а Web Animations API — для переходов, требующих измерения элементов.
- Если таймер служит запасным завершением для `animationend`, оба пути должны безопасно вызываться повторно.
- При FLIP-анимации измерять координаты до изменения порядка DOM и очищать временный `will-change` после завершения.

## Проверка изменений

- Сохранять контракты селекторов и `data`-атрибутов Blade.
- При переносе общих стилей проверять настольные и мобильные правила.
- Проверять все страницы, подключающие общий скрипт, а не только страницу, на которой обнаружена проблема.
- Запускать проверку синтаксиса JavaScript и производственную сборку Vite.
- Не включать в изменение посторонние файлы из рабочей директории.
